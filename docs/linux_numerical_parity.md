# Linux formula arithmetic reference

The Linux x86_64 formula reference uses R 4.6.2, one BLAS thread, and
OpenBLAS 0.3.26 with `OPENBLAS_CORETYPE=Haswell`. The Linux R CI lanes set
this kernel explicitly so hosted CPU changes cannot silently change the oracle.
Haswell uses the AVX2 capabilities available on the reference workers, avoiding
the AVX512 requirement of the earlier Cooperlake diagnostic kernel.
The existing macOS references remain unchanged. All comparisons retain exact
floating-point bits, attributes, input order, and rejection decisions.

Linux R accumulates means, finite per-argument sums, column sums, and BLAS vector norms using x87 extended
precision. The Rust core implements those reductions directly, retaining the
extended result until R's corresponding conversion to binary64. Polynomial QR
uses the reference kernel's reduction order and fused operations. The scalar
Rust implementation of the vector reduction schedule requires no AVX CPU.
Both the standalone executable and R wrapper call this same Rust code.
The fitting rank policy and general fitting algorithms are unchanged.

The independent Linux snapshots were generated by original R's base/stats
functions in [this diagnostic run](https://github.com/deminden/rsdeseq2/actions/runs/41312179934),
using the committed generator bodies. The diagnostic copies omitted the unused
DESeq2 installation guard; their metadata explicitly records that DESeq2 was
not installed or used. The generators now require only their actual R version
and JSON writer dependency. No reference expectation comes from rsdeseq2.

On a Linux x86_64 reference worker supporting the selected OpenBLAS kernel:

```sh
python scripts/validation/check_linux_formula_references.py \
  --rscript Rscript --output-dir /tmp/rsdeseq2-linux-formula-reference
```

This regenerates all seven panels and compares every non-provenance field with
the frozen Linux snapshots. The required R CI lane also performs this check.
The snapshots preserve the results of a specific numerical environment;
changing the BLAS kernel can change R's high-degree polynomial basis substantially.
Full R-wrapper CI additionally compares model frames and formula attributes
against live original R in the same pinned environment.

## Complete fitting matrices and portable boundary checks

The 32-case complete-fitting panel now has a Linux x86_64 snapshot generated by
original R in [the dev reference run](https://github.com/deminden/rsdeseq2/actions/runs/43207011413).
The live original-R comparison passed before the package check. Nine polynomial
or ordered-factor cases differ from the macOS snapshot in 192 matrix entries;
the maximum absolute difference is `1.11e-16`. Inputs, labels, dimensions and
offsets are identical. No macOS reference or tolerance changes.
The [reference proof](data/dev-ci-formula-2026-11-12.json) records the independent
source hash and the complete set of platform differences.

The Rust test uses the existing platform-reference selector, and the pinned
Linux lane regenerates and compares this snapshot alongside the other six
panels. The independent generator's numerical output is preserved exactly;
only BLAS/LAPACK metadata paths are displayed as library basenames. Reference
artifacts are saved even when a subsequent comparison fails.

The elementary-function boundary panel has one portable snapshot, shared by
Rust tests and the actual-interface checker. It must not acquire a Linux suffix:
that previously selected a nonexistent file and prevented the remaining R
interface checks from running. Required platform-specific panels still fail
when their snapshot is missing; there is no fallback or wider numerical bound.

## Far-tail bounded posterior density

The original Linux R 4.6.2 density evaluation rounds its square and addition
separately; the existing macOS reference uses a fused operation. A one-ulp
log-density difference can grow when a posterior variance subtracts close
moments. In the independently generated half-uniform profile at estimate
`-40` and standard error `0.15`, the macOS expression missed the original Linux
posterior SD by `4.10e-6`, exceeding the existing `2e-6` bound.

The Rust density helper now uses the original Linux expression on Linux x86_64
and retains the existing expression on other targets. The standalone and
wrapped interfaces share this helper. The Linux fixture comes from
[original R and ashr in CI](https://github.com/deminden/rsdeseq2/actions/runs/43210948289);
all numerical reference fields are preserved. Tests check the density probe's
exact bits as well as every existing posterior accuracy bound. The macOS
reference and all tolerances remain unchanged. The
[diagnostic proof](data/dev-ci-uniform-2026-11-12.json) records the source hashes
and failing case. This correction affects bounded and location-prior helpers;
the default quantification and normal-mixture fitting paths are unchanged.
