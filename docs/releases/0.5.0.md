# rsdeseq2 0.5.0

Prepared release; no tag or package publication has been performed. This minor
release completes the documented standalone Rust numerical engine and includes
intentional formula, query-validation and public Rust API corrections after
0.4.0. It does not implement the complete DESeq2/Bioconductor surface.

## Changes

- Supported normalization, fitting, inference, transformations and optional
  ashr/apeglm calculations run in shared Rust. R translates arguments and
  constructs objects; restricted supported expressions are translated to Rust.
- Posterior probability summaries retain their coefficient identity. Queries
  reject mismatched coefficients and inconsistent matrix/vector shapes.
  A private identity field means downstream code obtains posterior objects from
  fitting APIs instead of constructing them with struct literals.
- Formula interactions simplify repeated variables while preserving additive
  groups, dot expansion, R term order and factor coding. Combinatorial expansion
  and nesting are bounded before matrix construction.
- Posterior grids expose estimated work, default to a batch budget of ten million
  likelihood evaluations, and support configurable limits and cooperative
  cancellation. Native R interruption is contained safely; callback thread
  affinity and post-cancellation reuse are tested.
- CLI diagnostic writers borrow Cook's matrices from retained fits, removing
  three unconditional full-matrix copies.
- Tooling is grouped by purpose, current guides are separated from historical
  evidence, and operational R locks live in `config/r-reference/`. Internal Rust
  validation tools retain their explicit Cargo targets after relocation.
- The root quickstart example is removed. CLI documentation uses caller-supplied
  count/design tables. OS metadata is ignored and excluded from Rust/R packages.

## Numerical and performance evidence

The [correction report](../reports/review-fixes-2026-11-12.md) records passing Rust,
both R lanes, five platform panels, full GTEx parity and Linux ASan/UBSan before
this layout/version-only preparation. Local preparation checks are documented in
[the reorganisation report](../reports/reorganisation-0.5.0.md).

Frozen reference values and numerical bounds are preserved. Production Rust
source remains byte-identical to the validated implementation; the release
version changes package/CLI version metadata. Original artifact-bound timings
retain their source identities and are not relabelled as a new 0.5.0 benchmark.
The main README continues to compare precision, speed and memory with original
DESeq2; development-to-development observations remain in the detailed reports.

## Distribution

The Rust crate, R package, R backend and vendored core use version 0.5.0. The
[release procedure](../release.md) validates the selected committed source and
five target archives before publication. Linux R package checks retain the known
compiled-symbol warning from the Rust runtime; this is not a CRAN-acceptance claim.
