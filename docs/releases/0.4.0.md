# rsdeseq2 0.4.0

Version 0.4.0 gathers the changes since 0.3.1 into a minor release. Formula
coding, validation and fitted-state behavior include intentional compatibility
corrections. Versions agree in the Rust crate, R package, backend, vendored core
and both lockfiles.

## Changes

- Supported formula expressions, frame preparation, categorical coding, offsets
  and model-matrix construction share the Rust numerical engine. Custom formula
  functions are rejected before execution; R retains symbolic metadata,
  argument translation, identifier alignment and object construction.
- Ordered-factor coding, unused levels, factor conversion, higher-order
  interactions and multiplication order follow independent original-R references.
  Expanded-factor recoding for normal shrinkage also runs in Rust.
- Linux x86_64 uses Rust-owned extended-precision reductions and a fixed Haswell
  BLAS arithmetic schedule. Original R independently regenerates six exact
  reference panels in required CI, including ordered factors through 95 levels.
  Finite sums retain R's per-argument rounding boundaries. See
  [Linux numerical parity](../linux_numerical_parity.md).
- Wald/LRT inference, contrasts, Cook's and zero policies, independent filtering
  and BH use the shared Rust engine. Fitted-state reuse and mutable inputs are
  validated; result batches and temporary allocations are bounded.
- Rank/reduced-model, normalization-offset and worker validation is hardened.
  Large implementation and test modules are refactored; repetitive tests are
  consolidated while retaining independent numerical coverage.
- Stable dependency updates include locfit 0.2.0 and L-BFGS-B 0.3.0. Distribution
  archives include the applicable third-party arithmetic license notices.
- Locked R dependencies have hash-verified CRAN mirror fallbacks. Verified
  dependency installations are cached independently of later package tests.

## Precision and validation

The numerical implementation checkpoint passes Linux Rust CI, both R CI lanes,
the full GTEx replay and all five release target checks. The release workflow
revalidates the tagged source before publishing checked source archives or
binaries. No numerical tolerance was relaxed; existing Mac expectations and
frozen GTEx export identities remain unchanged.

Validation includes 1,074 local Rust tests plus the Linux-only sum cancellation
case, three backend tests, 47 Python tests (one local platform skip), 2,615 local
R assertions, and exact direct standalone/wrapped interface comparisons. Clippy,
Rust 1.97.1 checks on Mac and Linux, vendor integrity and crate verification pass.
All 121 per-contrast and nine global GTEx precision gates pass, with all 22 native
result/diagnostic exports unchanged. All 20 paired R workflow payloads are
byte-identical to the preceding candidate.

R CMD check retains one compiled-code warning for termination symbols linked
from the Rust standard runtime. The numerical tests have zero failures; this
warning remains visible. This release does not assert CRAN acceptance.

## Speed and memory

One paired pass on Apple M5/macOS, with one Rust/BLAS worker and no discarded
outliers, covers eleven contrasts with all 56,200 genes:

| Tool | Summed process time | Maximum whole-process RSS |
| --- | ---: | ---: |
| rsdeseq2 0.4.0 | 36.273 s | 302.063 MiB |
| Original DESeq2 1.52.0 / R 4.6.2 | 189.251 s | 1,764.531 MiB |

The observed original-DESeq2/rsdeseq2 time ratio is **5.22×**. The previous
candidate takes 36.105 s; the 0.465% difference is a single-pass observation.
Twenty paired R workflows take 88.356 s versus 88.397 s previously and remain
below 2 GiB peak RSS. These measurements do not estimate run-to-run variability.
[Per-contrast tables, raw measurements and reproduction commands](../reports/gtex-native-wald-benchmark.md)
are committed alongside the immutable precision manifests.

## Supported scope

The [Rust-only wrapper migration](../history/rust-only-wrapper-migration.md) remains
unfinished. Frozen local VST reuse and optional ashr/apeglm posterior, scaling,
tail and s-value calculations still involve R. The documented argument/method,
warning and authoritative-result-path gaps remain outside this release's
compatibility claim. Full Bioconductor API compatibility is not claimed.
Ordered coefficients use named/numeric selectors; treatment-style level
selectors for ordered factors are rejected. Expanded ordered coordinates do not
certify unsupported DESeq2 source-ordered betaPrior routes.

## Distribution and reproduction

The coordinated tag workflow publishes the checked Rust crate and R source,
Linux x86_64/ARM64, macOS x86_64/ARM64 and Windows x86_64 CLI archives,
source/binary provenance and SHA-256 checksums. Each target runs release-profile
numerical and CLI checks. See [release procedures](../release.md).

```sh
cargo install rsdeseq2 --version 0.4.0 --locked
```

The [contrast generator](../../scripts/references/generate_gtex_mode_contrasts.py), benchmark
and independent R generators are included in the repository. For the exact Linux
formula references, use R 4.6.2 on a compatible Linux x86_64 reference worker:

```sh
python scripts/validation/check_linux_formula_references.py \
  --rscript Rscript --output-dir /tmp/rsdeseq2-linux-formula-reference
```
