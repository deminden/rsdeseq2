# Focused source refactor — 2026-11-12

This follow-up reorganizes six maintenance hotspots after the validated
`7223f23` checkpoint. It preserves public APIs, independent reference values,
calculation order and numerical bounds. Source changes are on `dev`; no tag,
release, registry publication or main-branch merge is part of this work.

| Builder dispersion/transforms | 938 lines | Six compiler-visible private stage modules: normalization, gene-wise estimation, trends, MAP, VST and rlog. All 43 method bodies retain their operations; 36 public signatures remain unchanged. Private helper visibility matches the former enclosing implementation scope. |
| Formula beta-prior adapters | 969 lines | Primitive/model-frame adapters, data-only input conversion, and shared size-factor/matrix-factor execution helpers. All sixteen public signatures remain; eight duplicated primitive execution paths now forward to the existing shared helpers. |

The formula conversions borrow the same inputs and move the existing options;
they introduce no allocations, statistical calculations or new dispatch policy.
Parsing still precedes normalization and fitting. The eight shared execution
bodies are unchanged apart from formatting. Rustfmt now follows the real stage
modules; optional trailing call commas and single-call closure blocks account
for formatting-only token changes.

The reference generator's calculations remain independent original R/DESeq2
code used only for validation. Production R still transports arguments and
objects to the shared standalone Rust engine.

## One paired performance pass

These measurements compare the saved baseline and refactor artifacts with one
Rust/BLAS worker. Each case alternates execution order, with no concurrent task
fits or builds. Other user/system work remains uncontrolled. Every observation
is retained; no case is discarded or retimed and no optimization round is counted.

| Panel | Before | After | Observed change |
| --- | ---: | ---: | ---: |
| Eleven native contrasts, total process time | 82.275 s | 82.145 s | −0.16% |
| Native maximum process RSS | 306.625 MiB | 316.922 MiB | +10.297 MiB at the cohort maximum |
| Twenty R workflows, total process time | 197.684 s | 203.965 s | +3.18% |
| R maximum process RSS | 1,153.297 MiB | 1,153.484 MiB | Both below the predeclared 2 GiB budget |

Both native executables reproduce all **22 accepted result/diagnostic exports**
exactly, with all 44 frozen input/reference hashes unchanged. Every complete R
workflow payload is **byte-identical** under strict comparison; no migration or
numerical exception is enabled.

The native timing includes result **and diagnostic** serialization. The main
README's original-DESeq2 comparison times result output only, so these totals
must not replace that comparison. Its artifact identities and figures remain
explicit in the benchmark report; development memory deltas stay here.

The largest rlog case accounts for 3.73 s of the 6.28 s aggregate R difference.
Its instruction count is 0.07% lower after refactoring, while involuntary context
switches rise from 20,841 to 77,276 (3.71×). This documents scheduling interference
and essentially unchanged instruction work, but does not establish the cause of
the elapsed-time difference or prove exact R speed preservation. The +3.18%
observation remains visible. No statistical kernel was changed to chase that time.
